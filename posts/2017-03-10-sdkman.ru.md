# SDKMAN! - тул менеджмента SDK для разработчика на Java/Groovy/Kotlin/Scala и связанных фреймворков

Каждому разработчику, билд-инженеру и просто DevOps-у так или иначе приходится устанавливать и обновлять JDK/Ceylon/Groovy/Kotlin/Scala и Grails/Griffon/Spring Framework, а также связанные с ними системы сборки Ant/Maven/Gradle/Kobalt/sbt и проч.  
[http://sdkman.io/](http://sdkman.io/) - Unix-тул менеджмента разных версий SDK. Работает и под [Cygwin](https://www.cygwin.com/) на Windows.

![SDKMAN!](/assets/blog/sdkman/01.png)

Собственно как это выглядит, после запуска:  
1) инсталлятора

```
$ curl -s "https://get.sdkman.io" | bash
```

2) команды установки environment:

```
$ source "$HOME/.sdkman/bin/sdkman-init.sh"
```

## Установка SDK

### Последняя стабильная версия

Установка **latest stable** версии SDK (например, Java JDK) :

```
$ sdk install java
```

Покажет нам:

```
                                                    
Downloading: java 8u121

In progress...

######################################################################## 100.0%

Installing: java 8u121
Done installing!
```

После этого можно указать, что это будет версия **default.**

```
Do you want java 8u121 to be set as default? (Y/n):
```

Соотв. при выборе *yes* (или нажатия *enter*) все открывающиеся shell-ы будут использовать версию SDK озвученную выше.

```
Setting java 8u121 as default.
```

### Заданная версия

Нужна **specific-**версия SDK? Просто укажем ее параметром:

```
$ sdk install scala 2.12.1
```

### Локальная версия

Нужна версия snapshot? У вас уже есть локальная инсталляция? Установите локальную версию:

```
$ sdk install groovy 3.0.0-SNAPSHOT /path/to/groovy-3.0.0-SNAPSHOT
```

## Удаление версии

Удаляем установленную версию:

```
$ sdk uninstall scala 2.11.6
```

## Использование сессионной версии

Для использовании определенной версии в текущем терминале (текущей сессии):

```
$ sdk use scala 2.12.1
```

## Использование версии по умолчанию

Для использования версии по умолчанию:

```
$ sdk default scala 2.11.6.
```

## Получение текущей версии

Для просмотра текущей версии компонента:

```
$ sdk current java
  Using java version 8u111
```

Для просмотра текущей версии **всех** компонентов:

```
$ sdk current
  Using:
  groovy: 2.4.7
  java: 8u111
  scala: 2.12.1
```

## Старые версии

Для просмотра старых версий компонента:

```
$ sdk outdated springboot
  Outdated:
  springboot (1.2.4.RELEASE, 1.2.3.RELEASE < 1.2.5.RELEASE)
```

Для просмотра старых версий **всех** компонентов:

```
$ sdk outdated
  Outdated:
  gradle (2.3, 1.11, 2.4, 2.5 < 2.6)
  grails (2.5.1 < 3.0.4)
  springboot (1.2.4.RELEASE, 1.2.3.RELEASE < 1.2.5.RELEASE)
```

Получить список сообщений об обновлении компонент:

```

* 23/11/16: Gradle 3.2.1 released on SDKMAN! #gradle
* 22/11/16: Ceylon 1.3.1 released on SDKMAN! #ceylonlang
```

Также сообщение будет получено, если выйдет новая версия компонента и будет выполнена любая команда. Каждое новое сообщение попадает и в Twitter.

## Offline-режим

SDKMAN! может работать в offline-режиме:

```
$ sdk offline enable
  Forced offline mode enabled.

$ sdk offline disable
  Online mode re-enabled!
```

В **offline-режиме** большинство команд работают. Например команда list, отображает только установленные и текущую активную версии:

```
$ sdk list
  ------------------------------------------------------------
  Offline Mode: only showing installed groovy versions
  ------------------------------------------------------------
   > 2.4.4
   * 2.4.3
  ------------------------------------------------------------
  * - installed
  > - currently in use
  ------------------------------------------------------------
```

Также offline-режим автоматически включается/выключается если доступно/недоступно соединение с SDKMAN! серверами.

## Обновление SDKMAN!

Можно обновить сам SDKMAN!:

```
$ sdk selfupdate
```

Если хочется принудительно переустановить:

```
$ sdk selfupdate force
```

## Flush

Время от времени необходимо сбрасывать состояние кэшей SDKMAN!. Команда flush делает это:

### Компоненты

```
$ sdk flush candidates
```

Очищает список компонентов. Открывает новый терминал, получает и сохраняет в кэше актуальный список компонентов. Обычно данная команда полезна, когда в списке компонентов SDKMAN! появляется новый компонент.

### Новости

```
$ sdk flush broadcast
```

Очищает новостной кэш и загружает последние новости на выполнении следующей команды.

### Архивы

```
$ sdk flush archives
```

Очищает все кэшированные SDK компоненты. Это может быть полезно для сохранения свободного места на диске.

### Временные файлы

```
$ sdk flush temp
```

Чистит временные файлы, необходимые для работы самого SDKMAN!.

## Конфигурация

Конфигурация расположена в `~/.sdkman/etc/config`:

```
# make sdkman non-interactive, preferred for CI environments
sdkman_auto_answer=true|false

# perform automatic selfupdates
sdkman_auto_selfupdate=true|false

# disables SSL certificate verification
# https://github.com/sdkman/sdkman-cli/issues/327
# HERE BE DRAGONS....
sdkman_insecure_ssl=true|false

# disable GVM alias, for users of the Go Version Manager
sdkman_disable_gvm_alias=true|false

# configure curl timeouts
sdkman_curl_connect_timeout=5
sdkman_curl_max_time=4

# subscribe to the beta channel
sdkman_beta_channel=true
```
